    - 権限委譲と期待値の伝達を軸に伴走した結果、メンバーが自発的にリリース簡略化Pipeline・作業テンプレート・自動化Skillを作成
  - リリースごとに再発していたブランチのコンフリクトについて、squashマージによる履歴の断絶が原因であることを特定し、マージ運用を再設計してチームに展開
  - Google Playのtarget API 36 / 16KBページサイズ対応を調査。ELF検査スクリプトでサードパーティSDKの非対応を特定し、ベンダー依存のクリティカルパスを切り分け
  - 本番不具合（生体認証ダイアログとキーボードの干渉）の原因特定から修正・hotfixリリースまでを担当し、潜在不具合も合わせて洗い出し
  - Firebase App Distribution + IP制限付きWeb配信によるプロトタイプ配信基盤を拡充（約70画面の画面カタログ）。業務部門がリリース前にWeb版で仕様確認できる運用を実現

- **認証基盤移行プロジェクト(2026年9月〜現在)**
  - Azure AD B2CからAuth0への移行計画を策定
    - 4領域（認証・移行・バックエンド・アプリ）の詳細WBS約200項目を統合し、マイルストーン・リスク・判断ポイントを整理
    - 対外マイルストーンと内部目標を分けてバッファを可視化し、2027年6月のリリースに向けた計画をAzure DevOpsのバックログ（Feature / User Story / Task）まで落とし込み

- **テスト自動化・品質基盤の整備(2026年4月〜現在)**
  - リリース前のデグレ検知を目的にMaestroによるE2Eテストを導入
    - iOSで入力が空打ちになる偽陽性を、FlutterのSemantics identifierを体系的に導入して根治
    - Maestroが通信を観測できない制約に対し、モックサーバー側でリクエストを記録・照合する方式を考案し、APIコントラクトの検証まで自動化
    - 目的から逆算して検証環境を一本化する方針を提案・合意形成し、保守対象のテスト資産を大幅に削減
  - 既存テストを全数監査し、過剰なテスト約70件を削減。CIにキャッシュ・シャード並列を導入し、テスト時間を10.7分→3.4分（-68%）に短縮
  - 変異注入でテストの検知力を測定し、「通っているが壊れても気づけない」テストを可視化
  - E2Eの実行時間（1周約23分）を課題に、Dart VM上で実アプリ全体を動かすジャーニーテスト基盤を設計・実装（1ジャーニー数秒で実行）

## 自己PR
Flutterを中心としたクロスプラットフォーム開発を得意としています。UI実装だけでなく、状態管理やAPI連携、パフォーマンス改善などにも関心があります。
また自動化という文脈に強い興味があり、CI/CDの導入やテスト自動化に取り組んできました。
2026年にはインフラ領域（Terraform・Azure）も経験し、現在は認証基盤の移行計画とモバイル横断チームの立ち上げに取り組んでいます。
生成AIにテストや開発を任せる仕組みを作りつつ、「AIに任せた結果を人間がどう検証するか」を定量的に確かめながら進めることを大切にしています。
チームリードとしては、自分がいなくても回る仕組みを作り、メンバーが自発的に改善を生み出せる状態を目指しています。
趣味の延長で小中学生のバドミントンのコーチを5年ほど続けています。人と接することが好きで、チームメンバーとの密なコミュニケーションを大切にしています。
